# MacBook Neo J700

This is the `j700` branch of `aurora-silicon/linux-aurora` for MacBook Neo
**J700 / T8140 / Mac17,5**. The companion Mesa branch is `j700` in
`aurora-silicon/mesa`; the m1n1 branch is uppercase `J700` in
`aurora-silicon/m1n1-aurora`.

## Recorded desktop checkpoint — 2026-09-11

The qualified runtime uses kernel `7.1.6-aurora-neo-gpu1` and Mesa merge
`c8d98bcc1000`, which includes DJ's `agx3` work through `ba7aee4190b`.
Native DCP scanout, KDE Plasma 6.7.5 X11, KWin GPU compositing and
Zink/Honeykrisp gears ran on the Neo. Wi-Fi connected and appeared in KDE's
Networks panel; Bluetooth powered on and discovered devices while Wi-Fi
stayed connected.

The [composited cursor helper](tools/aurora/neo-encoding/desktop/README.md)
keeps the pointer in KWin's completed frames. The initial Plasma lock/unlock
check passed, and all 2,288 scanout samples matched the selected cursor
pixels. Linux commit `7841f6a61e7d` contains the helper; Bluetooth commit
`cc917e8e1798` is retained in its history.

The later device-loss recovery change pairs Mesa's WSI/syncobj wait fix with
the [KWin recovery service](tools/aurora/neo-encoding/desktop/README.md#recovering-kwin-after-gpu-device-loss).
A GPU job failure reported by firmware had left KWin waiting indefinitely
for an unsignaled semaphore. The Mesa fix rejects that wait after device
loss; the service restarts KWin when the current process reports device loss
and bounds compositor shutdown to five seconds. Live process-local error
injection restored compositing in 6.5 seconds. The final runtime passed eight
lock/unlock cycles, showed changing gears frames and matched all 2,264 cursor
samples. The test injector was removed after qualification.

These results have specific limits:

- The cursor helper is an X11 workaround. It does not add a hardware cursor
  plane or qualify Wayland. Qt Quick shell rendering remains on software.
- DPMS is disabled and PowerDevil is runtime-masked because DCP display resume
  remains unresolved.
- Wi-Fi startup uses a console-log timing workaround and starts WLAN before
  Bluetooth. The combined helper passed on a fresh boot when run manually;
  the saved systemd override still needs an automatic fresh-boot check. The
  underlying TX17 timing problem is not fixed.
- The initiating GPU job failure and Zink's post-loss context teardown loop
  remain unresolved. The tested recovery path handles reported device loss;
  it does not establish reliable recovery from every GPU or DMA fault.

Host-side deployment scripts, matching binaries, captures and logs are kept
in the separate private `neo-linux` workspace. Its `HANDOFF.md` points to
the recorded `agx3-ba7aee4-20260911`, `plasma-wifi-20260911` and
`kwin-freeze-20260911` campaigns.
A clone of this repository does not include those runtime artifacts.

Before hardware work, verify the connected target is T8140/J700. J813/T8142
is a separate machine; serial ordering and a default port do not establish
identity. Preserve resident Stage 1 and use the qualified guarded RAM boot
workflow. Keep existing worktrees and qualification archives when cleaning
the workspace.
