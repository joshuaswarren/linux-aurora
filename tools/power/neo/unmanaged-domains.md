# Unmanaged J700 domains: experiments, not a shutdown policy

Claude's 2026-09-15 inventory broadened the search beyond Linux's live genpd
providers. The retained ADT contains 296 device entries, including virtual
entries. `j700-pmgr-domains.json` is regenerated by `pmgr-table.py`; original input is
workspace `artifacts/neo-suspend/dcp-pmgr-native/adt-pmgr.json`, SHA256
`211b4c39963829532b1e9c60e47027059d039b7c338205043c152b5caf3f4193`.
An ON register read taken awake is not proof of the state throughout sleep,
and absence of a Linux consumer is not proof that firmware never accesses it.

Claude's first PRORES+MSR gate reached actual 0 and lowered the first SMC PSTR
reading after a 20s sleep from about 0.7702 to 0.7535 W. This is a promising
screening result, not a calibrated sleep average. The original restore passed
`f` to base-0 strtoul, silently setting target 0 instead of 15. Both blocks
therefore stayed off; restoration was not qualified. A subsequent external
display trial gated GPPP/DBE, then stopped at a DISPEXT0_CPU write and required
DebugUSB recovery. Do not repeat CPU-domain writes from this tool.

The imported tools have now been tightened:

- C numeric parsing rejects partial/overflow/unaligned arguments before MMIO.
- Restore requests explicit `0xf`, verifies ACTIVE, restores original AUTO
  policy if needed, and checks policy readback. Failed writes/reads abort.
- Restoration records retain readbacks and boot ID; cross-boot replay is
  refused. Restore failures keep unresolved state and stop before children.
- CPU domains and busy/reset/device-disable words are rejected. Powered
  children, including descendants behind virtual entries, prevent gating;
  there is no force bypass.
- The outer trial exits unsuccessfully on failed sleep, failed restore,
  storage/network recovery or increased PM failure counters. An IPv4 address
  alone no longer counts as network recovery; association and gateway response
  are required. No hardware test is implied by these offline checks.
- PM snapshots now record Type-C roles/partners and battery/AC state. The
  unexplained +1.2 W in earlier awake AND sleep measurements makes changed
  physical/boot state a lead; it does not prove which load was responsible.

The SMC series immediately after wake is useful for fast screening. Values
can be stale and are not an integrated sleep measurement. `sleep-smc.py` now
ends its battery-counter interval before the following four seconds of awake
SMC sampling and rejects external-power/non-discharge samples. Use a fresh
awake calibration and 120s battery-counter ABBA to confirm any proposed saving.
SMC rail names/overlaps alone do not establish an exhaustive power budget.

## First corrected hardware qualification

On unchanged kernel #40, boot 9e018be2-2a9d-4f7a-b66a-6e91b2be4e60,
the fresh 20s baseline's first post-wake PSTR was 0.774208 W. PRORES+MSR
gave 0.758828 W; awake PSTR fell 3.518191 -> 3.502073 W, then returned to
3.531646 W. These remain screening samples, not a confirmed sleep average.

Actual restoration now passed: PRORES 0x000003ff -> 0x00000300 -> 0x000003ff,
MSR 0x0f0023ff -> 0x0f002300 -> 0x0f0023ff. State records retained both
readbacks with restore_complete=true. RTC, panel, six CPUs, storage, Wi-Fi
association/gateway and PM failure-counter checks passed. Raw captures are
`domain-gate-review/{base-20,g1-20}/` locally and `domain-gate-v2/` on Neo.
The helper also now refuses domains enumerated in the live genpd summary,
in addition to its static exclusions.

## Inventory correction before further domain trials

The imported table resolved parent IDs as one-based row numbers. These diverge
later in the ADT, producing 77 parent-list differences, including a false
AOP_BASE self-parent and omitted high-ID virtual parents. The table also used
an offset-based virtual heuristic: only 69 entries were marked virtual.

Both m1n1's `src/pmgr.c` and native ApplePMGR::_syncDeviceStatusChange test
the first flags byte's 0x10 bit and skip direct power-state register operations
for those entries. Applying that flag gives **197 virtual and 99 physical**
descriptors. DPTX_PHY, SIO, AOP_CPU, DISPEXT0_GPPP and DBE are among entries
marked virtual by the native convention, even though their offset fields are
nonzero and a read there can return an ON-looking word. Those words do not
authorize AP power-state writes. The large earlier unmanaged-ON count is not
a qualified count of independent gateable hardware blocks during sleep.

`pmgr-table.py` follows the 16-bit id2 parent lookup and ps-groups mapping,
checks unique IDs/names and a cycle-free parent graph, and retains device_id
separately from adt_index. Regenerate with:

```
python3 tools/power/neo/pmgr-table.py ../artifacts/neo-suspend/dcp-pmgr-native/adt-pmgr.json --output tools/power/neo/j700-pmgr-domains.json
```

PRORES/MSR offsets, physical flags and parents are unchanged, so their ongoing
ABBA remains applicable. No other gates were attempted during this audit.
The old table is retained as `domain-gate-review/claude-domain-table.json`.
Next candidates are physical leaf UART1–3 and SPI0–2, which have no matching
clock-gate consumer nodes in the saved board ADT. This absence is a screening
criterion, not proof that a firmware consumer cannot exist. SPI3 is the panel
SPI node, UART4/5 are radio debug ports, QSPI owns NOR/NVRAM, and I2C0 owns the
audio codec: don't lump those together as anonymous unused leaves.

## Sleep-only media hook candidate

`overlay/neo-media-sleep.c` gates only PRORES and MSR in suspend_noirq and
restores them in resume_noirq. Default enabled=N. It rejects DT-described
providers for these offsets, unsafe initial words and non-s2idle requests;
it retains partially touched state and verifies ACTIVE/original policy during
restoration. No parent, virtual descriptor, CPU, firmware buffer or display
mapping is changed. The ordinary awake state is preserved after a successful
cycle. Do not operate the userspace gate helper on those domains while this
hook is enabled. Its parameters expose pending/failed and cycle counters;
PM snapshots and health validation check unresolved transitions.

The module builds against #40; hardware qualification is pending. This is a
board-specific experimental sidecar, not a replacement for eventual consumer
drivers and genpd ownership. A failed restoration requires recovery rather
than treating a module unload or successful PM write as a healthy machine.
