The integration retains the local depth/storage-image paths and positionless
UVS staging. Internal G17P kernels retain the 12-half hardware uniform prefix
while using upstream's real printf address after their arguments. Both
Gallium and Vulkan upload that ABI. Returned atomics now use the upstream
native layout above the spill frame. The optional ballot source-cache hint
is separate from source lifetime, preserving both native witness encodings.

Build fixes included the new layer-as-varying lowering arguments and a
duplicate R32 tile-format case. The unit suite caught an upstream stack
overwrite in `agx3_alu_fadd_minifloat`: six base fields plus six waits required
12 entries, while the array had 11. The existing exhaustive ALU test passes
after correcting that capacity. The coherent event-poll byte expectation
now matches the new explicit coherent load field; all other bytes stayed equal.

## Validation

- Complete isolated Mesa build succeeds (`native-visibility-build*.log`).
- `agx_tests`: 496 tests passed, one disabled test remains disabled.
- ALU, subgroup and event-wait focused retest: 3/3 pass.
- Precompiled metadata test passes, including the preserved tessellator
  footprints and new printf offsets. Metadata dump:
  `native-visibility-metadata.json`, generated by `probes/precompiled-metadata.c`.
- Most recent full Asahi suite (`native-visibility-asahi-tests6.log`):
  294 OK, 2 expected failures, zero unexpected failures out of 296.
  Indirect launches now publish their existing weak tail marker, allowing an
  explicit HOST_READ flush to strengthen that record rather than append an
  adjacent barrier. The conditional-compute oracle now expects both required
  strong tails: predicate-to-consumer and consumer-to-host. Launch and barrier
  counts remain three each. This is host/shim validation, not hardware CTS.
- `--no-rebuild` on a fresh build initially missed standalone GL probes because
  they are `build_by_default: false`; normal `meson test --suite asahi` builds
  them and runs all 296. Earlier missing-executable failures were build setup,
  not GPU results.

The new Vulkan HOST_READ path creates strong barrier roots. Merging those
roots after an existing launch tail could duplicate barriers. The integration
coalesces the leading strong flush with an existing weak/strong tail, including
roots with following commands. Tests verify bytes, markers, counts and lack of
extra jumps. The shim now admits a standalone strong cache-flush stream while
still rejecting a completely empty stream. Four exact stream-count expectations
were updated for the newly emitted explicit HOST_READ boundaries; launch counts
were unchanged. The final nine failures are resolved by the indirect-tail
marker correction and the exact conditional-compute flush-count update.

## Next work

Investigate the Gallium CPU-read visibility boundary alongside the new kernel render publication/cache
changes. The Vulkan HOST_READ fix is a relevant lead, not a demonstrated Gallium
fix. Preserve batching; do not add per-draw barriers, sleeps or read retries.
Run the fail-fast readback probe before the official failure replay, then use
the full official campaign only when the defect is cleared.
