# Official GL3.0 X11/EGL inventory and first baseline

The unmodified `x11_egl` build of CTS tag `opengl-cts-4.6.8.1` is installed at `/opt/neo-cts-opengl-4.6.8.1-x11`. Source commit `067e8832315e79817ede1c4863804e440f5d1c80`, clean tagged source, both executables built for AArch64, all 1,182 packaged files verified. Package SHA256 `eb082f8382f0a4e47f6a95ae6f4c77cc9fbe311df61639a0555678c3e7bf666a`.

The official `cts-runner --type=gl30 --summary` selects 52 sessions: one configuration metadata session, one no-error-context case, and 50 complete executions of the 878-case main list. Those 50 comprise two window sizes/seeds for each of 24 framebuffer configurations and two FBO variants. Total selected test executions: 43,901, plus 15 configuration metadata cases. This supersedes the six-session surfaceless fallback inventory.

Native client renderer is verified as Mesa / Apple A18 Pro GPU / OpenGL 4.6 Compatibility Profile. The library advertises that version; conformance is not proven. There are no capability/version overrides, waivers, or Zink in the CTS client. The dedicated Xorg server uses its separate, previously working Zink backend to present windows on DCP. Mesa's normal device selection bridges the display-only DCP and Asahi render devices; forcing `MESA_LOADER_DRIVER_OVERRIDE=asahi` without PRIME wrongly applies the render driver to the display FD and fails EGL initialization.

The first full X11 run (`hardware-inventory/x11-baseline`) completed 33 Pass, 4 Fail and 3 InternalError results. It then aborted in `KHR-GL30.transform_feedback.draw_xfb_test`. The ledger retains one Incomplete case and 43,875 NotRun entries. Only two of 52 sessions completed. No kernel GPU fault or kernel-stream overrun was recorded. These are partial results, not a conformance verdict.

Instrumentation reproduced the abort and identifies a direct triangle-strip command with zero vertices and one instance. `agx_draw_vbo_from_xfb` resolves an empty stream-output counter into a zero-count direct draw; the G17P packet encoder correctly rejects zero counts, but the draw frontend failed to treat the command as a no-op. The fix returns before shader/query/batch work for direct draws with zero vertices or instances, preserving indirect draws and packet validation. The same official hardware diagnostic now completes with Fail instead of aborting. Transform-feedback rendering and clipping failures remain unresolved.

The full rerun with that fix records 34 Pass, 14 Fail, 3 InternalError, 1 ResourceError and 43,864 NotRun entries. Only two of 52 sessions complete. A GMMU read fault appears in the first R8 texture-repeat case; the next case sees the resulting lost GPU state. The first R8 case independently reproduces the fault on a fresh boot, establishing that prior transform-feedback failures are not required. The supervisor stops GPU work on a fault and each subsequent hardware attempt uses a fresh boot.

A proposed mipmapped-texture layer-flag change passed an added capture comparison but did not fix the isolated hardware fault. That hypothesis and its added tests were set aside; the original capture did not independently establish backing-allocation invariance. The source is restored to the verified empty-draw implementation. Command/descriptor tracing is the next diagnostic step. CTS source, expectations and complete acceptance inventory remain unchanged.
